## 问题与原因
- 首页报错：在 `HomeScreen` 渲染期间触发了 `setState`，因为我把 `loadByDate(todayISO)` 放在 `useMemo` 中，导致渲染时更新 store。
- 无法退出登录：`profile.tsx` 的退出按钮只调用了 `useAuthStore.logout`，未调用 Supabase 的 `signOut`。根布局根据 Supabase `session` 判断已登录，因而重定向回首页。

## 修复方案
1) 首页渲染期更新状态错误
- 将 `useMemo(()=>loadByDate(todayISO), [])` 改为 `useEffect(()=>{ loadByDate(todayISO) }, [todayISO])`，避免在渲染路径更新状态。
- 保持 `SummaryCard` 与列表数据来源不变，Loading 用现有 `loading` 标记。

2) 退出登录与路由守卫
- 在 `app/(tabs)/profile.tsx` 中引入 `useSupabaseAuthStore`，退出时先 `signOut()` 再 `logout()` 并 `router.replace('/(auth)/login')`。
- 根布局已按 Supabase `session` 或本地 `user` 判断访问权限，保证退出后进入登录页。

## 验证
- 打开首页不再出现“Cannot update a component while rendering”错误，数据加载正常。
- 在“我的”页点击退出登录后，跳转到登录页；刷新仍处于未登录状态。

## 备注
- 若还有 Supabase 表/函数未创建导致数据为空，前端已做降级查询；建议按前序指引在 Supabase 控制台补建表、策略与 RPC 并重置 API 缓存。
